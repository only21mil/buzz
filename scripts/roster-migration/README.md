# Sats roster migration bundle

This Buzz-owned bundle renames four existing Buzz agents without rotating their runtime slugs, Nostr keys, homes, state, secret-variable names, channel memberships, or ports. It also retires only the `sats-hermes` Buzz agent identity.

`roster.json` is the review contract. It contains public identities, public channel UUIDs, paths, models, and reasoning settings. It contains no private key, auth tag, proxy credential, or private message.

The installer is intentionally inert without `--apply`. A live run also requires `--execute-external`. It creates a new mode-0700 receipt directory and mode-0600 backups before the first relay or service action. The shared secrets file is backed up whole, but receipts expose only metadata and SHA-256 digests. Commands suppress output so a provider or relay failure cannot echo credentials.

The installer puts executable fleet code in `/home/victor/.local/libexec/buzz/fleet/roster-5ac44f9f-v1` and prompt configuration in `/home/victor/.config/buzz/agents`. The user service template points only to that installed code. It also installs a Buzz-owned desktop entry and launcher bound to the reviewed `0.5.9-test.11` artifact. The launcher uses the absolute `#!/usr/bin/bash -p` interpreter so Bash ignores `BASH_ENV`, `SHELLOPTS`, and imported functions before the first script statement without a recursive bootstrap or environment marker. It still clears every exported variable and unexpected function, then rebuilds an asserted allowlist containing only fixed runtime values, validated display sockets, cache paths, relay URL, and owner identity needed by Buzz. Its private working copy of `XAUTHORITY` is explicitly de-exported before that clearing step, so an inherited exported variable with the same internal name cannot unset launcher state. X11 and XWayland use an exported `XAUTHORITY` when supplied or fall back to `/home/victor/.Xauthority` when it is absent. Either path must be absolute, canonical, regular, readable, owned by Victor, and not group/world-writable; pure Wayland exports no `XAUTHORITY`. Immediately before execution, the launcher also revalidates the AppImage as a readable executable, Victor-owned, single-link, non-symlink regular file that is not group/world-writable, and validates every parent below `/home/victor` as a canonical Victor-owned directory that is readable, searchable, and not group/world-writable. The existing channel-sweep timer keeps its unit name, and its directory-sync entry point becomes a compatibility shim that executes the Buzz-owned publisher. No installed service or launcher points at the old Simplelift checkout or its `0.5.8` artifact.

Membership-sweep code is not copied by this roster bundle. It is an ordered dependency on the separately frozen Mempool/Genesis activation candidate: source tree `191cc2831e94c9aa60a2dd91ff67aedb280c2155`, staged-diff SHA-256 `107c26530f020af6d9bafa46db79012f7afc134d50bbd043bccc1daa545ca1d2`. A check, apply, or verify requires the later generated activation manifest path and its exact reviewed SHA-256. Before any roster mutation, the migration binds that manifest to the frozen source tree and generator-source hashes, verifies the generated package bytes and manifest `ops_targets`, and verifies the installed mode-0700 sweep at `/home/victor/.local/libexec/buzz/buzz-sats-channel-sweep` plus the mode-0600 user service that directly executes it. This leaves no mutable `~/.agents/tools` sweep dependency and makes a missing, stale, or not-yet-reviewed activation package a hard cutover block.

Before any mutation, the library rejects mismatched live/dry-run modes, unsafe install roots, malformed or duplicated Hermes secret assignments, and unsupported states across all fifteen affected units. It validates the full owner, directory-type, and non-group/world-writable chains for both `~/.local/share/applications` and `~/.agents/tools` before the desktop-entry write or directory-publisher import. A transiently activating membership sweep gets a bounded stable-state readback instead of an immediate false failure. Unsupported non-sweep units fail once with their exact unit name and are never mislabeled or pointlessly retried as sweep instability. The preflight verifies the exact Buzz CLI, systemctl, Python interpreter, reviewed publisher, installed `nostr_min.py` dependency chain, and desktop artifact digests. It verifies the Victor owner key without printing it, snapshots the existing kind-0 `name` and `display_name` independently for all four surviving identities, and strictly parses the Buzz CLI's exact `[{"pubkey": ..., "role": ...}]` membership shape for all 27 channels. Empty, malformed, duplicate, extra-key, or invalid-role membership data fails before backup or mutation. Those public values, tool digests, and unit states are bound into the private receipt.

The ordered live operation is: stop the standing channel-sweep timer and wait for both the timer and any running sweep service to become inactive, disable and stop the exact Hermes agent instance and reaper timer, self-archive Hermes, leave and read back all 27 memberships with a bounded convergence retry, atomically install the reviewed agent and desktop launchers, desktop entry, eight surviving prompts, user service template, proxy patches, and directory publisher, remove only the two Hermes variables from the shared secrets file, reload systemd, restart each of the eight retained agent units and three retained proxy units only when its recorded active state requires it, read back all eleven exact states, publish/read back the four kind-0 display-name changes without changing their independent `name` fields, publish/read back kind-10100 records through the sole directory writer, then restore the sweep service and timer to their recorded states. `payloads/profiles.json` records this distinction directly: kind-0 preserves `name` and changes only `display_name`; kind-10100 changes its reviewed directory names.

Every failure after the sweep stop triggers automatic recovery. Recovery stops and waits for both sweep units again, restores every backed-up byte and mode, restores relay state and the recorded kind-0 fields, and reconciles all eleven recorded unit states. A complete automatic recovery records `apply_failed_rolled_back`; an incomplete recovery records `apply_failed_partial` plus bounded error types and the attempted command list. It never reports success merely because file bytes were restored.

Operator rollback requires live external actions for a live-root receipt and forbids them for a fixture receipt. Before stopping or writing, it strictly parses all current channel memberships through Victor's verified owner identity. For every channel it restores the exact recorded role or absence and requires bounded exact-role readback before any unit restart; it does not assume self-join is authorized. If the owner command is unavailable or refused, rollback stops with `rollback_failed` and the operator must restore the named membership through an authorized owner client before retrying. It then restores the independently snapshotted kind-0 `name` and `display_name`, the previous kind-10100 names, and all eleven retained runtime states, with the sweep service and timer last. Offline verification reports relay membership as `not_checked`; only a live post-readback receipt may report `removed` or `restored`. Generic Hermes gateway and the Mempool/Genesis system agents, homes, state, templates, and binaries are never read or mutated.

Review commands:

```sh
python3 scripts/roster-migration/install.py
python3 -m unittest discover -s scripts/roster-migration/tests -v
```

After the separate activation package has terminal review closure, its controller supplies the generated manifest and digest to the read-only gate:

```sh
python3 scripts/roster-migration/install.py --check \
  --activation-manifest /absolute/path/to/package/bundle-manifest.json \
  --activation-manifest-sha256 REVIEWED_64_HEX_DIGEST
```

The parent lane owns the Tier 2 evidence preparation and every live cutover action.
