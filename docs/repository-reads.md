# Repository branch and lifecycle reads

`buzz repos branches --id buzz --owner <owner-hex> --json` lists all fetch-authorized hosted branches. Omit `--owner` for your own repository. `--repo-id` and `--repo-owner` are aliases. Without `--json`, output is tab-separated. Each branch has its exact tip, ahead/behind counts against the hosted default branch, `fully_merged`, commit timestamp and optional `open_pr_event_id`.

The relay endpoint is `GET /git/{owner}/{repo}/branches?offset=0&limit=200`. It uses the existing Git fetch access gate and exact URL/method NIP-98 authentication. The response contains `default_branch`, `branches`, `branch_limit`, `branches_total`, `next_offset` and a `snapshot` digest of the default ref and all branch metadata. Pages sort unmerged branches first, then commit time descending, then branch name ascending. The CLI follows pages and rejects changed ref snapshots or incomplete results. PR metadata can change between page requests.

A page inspects at most 200 branches' divergence, with a shared Git concurrency permit, 15-second inspection deadline and 1 MiB per-command output bound. PR association queries are bounded to 10,000 roots and 20,000 statuses; exceeding either returns an error rather than an incomplete answer. An announced empty repository returns an empty list. Missing repositories return 404; denied access preserves the fetch gate's response. Infrastructure failures and timeouts remain errors.

PR associations require an exact `branch-name` match; a shared commit alone does not link unrelated branches. Only current open roots are linked, excluding draft, closed and merged roots. Latest status uses timestamp descending and event ID ascending. Root markers take precedence over reply markers; legacy single `e` tags are accepted. This read recognizes status authors that are the PR author or repository owner. Other role/delegation authority is not inferred.

`buzz repos reconcile --repo-owner <owner-hex> --repo-id buzz [--limit N] [--json]` returns stable schema-version-1 JSON. JSON is the default. The command joins authorized NIP-34 issue roots, PR roots, PR updates, statuses and hosted branches. It writes no events, refs, issue statuses or PR statuses.

Each work-item row includes issue and PR IDs and status event IDs, the selected PR revision and exact commit, branch and hosted tip, merged-tip flag, claimed merge SHA, explicit superseding PR roots, closure claim and blockers. Multiple explicit issue links produce separate rows. Unlinked issues, PRs and branches remain visible. Titles and prose never establish coverage or closure.

The reducer uses `e` tags marked `issue` for issue links, `E` for same-author PR updates, and same-author PR roots referencing an earlier PR with an unmarked/root `e` tag for supersession. Latest statuses and updates use timestamp descending and event ID ascending. Status authority is conservatively limited to the root author and repository owner; unrecognized status authority is reported as a blocker. A closed root remains a closure claim even if its branch is absent or unmerged.

`--limit` applies after repository filtering and reduction. `items_total` and `items_truncated` expose display truncation. To support relays that apply coordinate filtering after SQL LIMIT, the command exhausts the authorized event-kind stream using composite cursor pagination before locally filtering repository roots. Legacy statuses without an `a` tag can therefore be joined by root ID. More than 100,000 events is an explicit read error. This addresses the omission documented in issue `af633f9f6be8c27c2261778c11fe52613583a68a47719148d553b3c8ad9d9fa5`.

This command is an evidence ledger, with `closure_verified: false`. It does not yet query GitHub mirror state or CI, verify the claimed merge's ancestry, or coordinate an atomic snapshot across refs and events. Those gaps are explicit in `coverage_gaps`; a merged-tip flag proves only that the current hosted tip is contained in the hosted default branch. Automation must require closure verification and no coverage gaps before treating a record as verified completion. CI/merge watchers and event-writing closure are outside this read-only command.
